Simulación de Procesos Productivos

Aprender simulación para tomar mejores decisiones

La simulación permite estudiar las relaciones entre los componentes de un sistema y representar su comportamiento ante escenarios posibles. En Ingeniería Industrial es una herramienta para analizar alternativas antes de intervenir directamente un proceso productivo, logístico u organizacional.

En este recorrido encontrarás lectura guiada, ejemplos, preguntas de comprensión y laboratorios. La meta no es solamente obtener un resultado: debes ser capaz de explicar por qué ocurre y cómo ese resultado puede apoyar una decisión.

UNIDAD 1

Conceptos de Modelamiento y Simulación

Propósito de aprendizaje: comprender qué significa simular, reconocer los componentes básicos de un modelo, diferenciar tipos de simulación, valorar sus ventajas y limitaciones y seguir una metodología lógica para desarrollar un estudio.

1. ¿Qué es un sistema?

Un sistema es un conjunto de elementos relacionados que interactúan para alcanzar un propósito. Una planta de producción, por ejemplo, integra operarios, máquinas, materiales, métodos, información, tiempos y reglas. El comportamiento global no depende solamente de cada elemento por separado, sino también de sus relaciones.

Entidades

Elementos que fluyen o son procesados: productos, pedidos, clientes, piezas o vehículos.

Recursos

Elementos necesarios para ejecutar actividades: máquinas, operarios, equipos y espacios.

Variables

Características que pueden cambiar: inventario, longitud de cola, producción, tiempo de espera o demanda.

Reglas y restricciones

Condiciones que gobiernan el sistema: capacidad, horarios, prioridades, secuencias y disponibilidad.

2. Modelo y modelamiento

Un modelo es una representación simplificada de la realidad. Modelar implica seleccionar los aspectos relevantes del sistema para responder una pregunta. Un buen modelo no necesita copiar cada detalle de la realidad; debe contener suficiente información para cumplir el objetivo del estudio.

Ejemplo: si queremos estudiar la capacidad diaria de una línea, pueden ser importantes los minutos disponibles, tiempos por unidad y número de máquinas. El color de las máquinas probablemente no aporta al objetivo y puede excluirse.

3. Definición de simulación

La simulación consiste en experimentar con un modelo para estudiar cómo se comportaría un sistema bajo determinadas condiciones. Permite plantear preguntas del tipo ¿qué pasaría si...?: ¿qué pasa si aumenta la demanda?, ¿si agregamos una máquina?, ¿si disminuye un tiempo de proceso?, ¿si aparecen fallas o llegadas variables?

Simular no es simplemente calcular. El valor de la simulación está en construir una representación coherente, experimentar con escenarios, interpretar resultados y apoyar decisiones.

4. Tipos de simulación

Discreta

El estado cambia cuando ocurren eventos identificables. Ejemplos: llegada de un pedido, terminación de una pieza, entrada de un cliente.

Continua

Las variables cambian continuamente con el tiempo. Ejemplos: nivel de un tanque, temperatura o ciertas dinámicas poblacionales.

Determinística

Las entradas se consideran conocidas. Con las mismas condiciones se obtienen los mismos resultados.

Estocástica

Incluye variables aleatorias. Tiempos, demanda, fallas o llegadas pueden variar entre ejecuciones.

Estática

No representa explícitamente la evolución temporal. Monte Carlo puede utilizar este enfoque.

Dinámica

Analiza cómo cambia el sistema a medida que transcurre el tiempo.

5. Ventajas de la simulación

Permite experimentar sin detener un sistema real; comparar alternativas antes de invertir; estudiar procesos complejos; identificar restricciones; observar efectos de cambios en capacidad, recursos o políticas; incorporar variabilidad; y apoyar la toma de decisiones con evidencia cuantitativa.

6. Desventajas y precauciones

Un modelo puede requerir tiempo, datos y conocimiento técnico. Si los datos son deficientes o los supuestos son incorrectos, los resultados también pueden serlo. La simulación no garantiza por sí sola la mejor decisión y no reemplaza el juicio profesional. Además, un resultado visualmente convincente no significa que el modelo haya sido validado.

7. Simulación frente a otras técnicas cuantitativas

Estas herramientas no son enemigas: pueden complementarse. Una organización puede pronosticar demanda, optimizar una política y después simular su comportamiento bajo variabilidad.

8. Pasos para desarrollar un estudio de simulación

1. Problema y objetivos

¿Qué decisión se quiere apoyar? ¿Qué pregunta debe responder el estudio?

2. Sistema y alcance

Definir límites, entidades, recursos, procesos, variables y supuestos.

3. Datos de entrada

Recolectar y analizar tiempos, demanda, llegadas, fallas y demás entradas.

4. Modelo conceptual

Representar el funcionamiento antes de programar o usar software.

5. Construcción

Implementar el modelo con la herramienta apropiada.

6. Verificación

Comprobar que el modelo fue construido de acuerdo con su lógica conceptual.

7. Validación

Evaluar si representa adecuadamente el sistema para el propósito definido.

8. Experimentación

Diseñar escenarios, ejecutar el modelo y comparar resultados.

9. Análisis

Interpretar indicadores y reconocer incertidumbre y limitaciones.

10. Decisión

Documentar conclusiones y recomendaciones.

9. Conceptos productivos que utilizaremos

Capacidad: máximo que un recurso puede procesar bajo ciertas condiciones. Producción/throughput: unidades que realmente salen del sistema. Utilización: proporción de capacidad utilizada. Cuello de botella: recurso cuya capacidad restringe el flujo. Demanda no atendida: diferencia entre lo requerido y lo producido cuando la capacidad no alcanza.

Capacidad aproximada = (tiempo disponible ÷ tiempo por unidad) × número de recursos
Comprueba antes de continuar: una máquina trabaja 480 minutos y tarda 6 minutos por unidad. ¿Su capacidad aproximada es 80, 120 o 480 unidades? Explica el cálculo antes de entrar al laboratorio.

UNIDAD 2

Generación de números aleatorios

Propósito de aprendizaje: comprender por qué la aleatoriedad es fundamental en muchos modelos de simulación, reconocer las propiedades deseables de las secuencias aleatorias y relacionarlas con la generación de variables aleatorias.

1. ¿Por qué necesitamos aleatoriedad?

En un sistema real no todo ocurre exactamente igual. Los clientes no llegan siempre cada cinco minutos, una operación puede tardar 4.1 minutos y luego 5.3, la demanda cambia y una máquina puede fallar en momentos distintos. Para representar esta variabilidad, los modelos estocásticos necesitan mecanismos que produzcan valores capaces de alimentar esos comportamientos inciertos.

Idea clave: el número aleatorio no es todavía el tiempo de llegada, la demanda o la duración de una operación. Normalmente funciona como una entrada básica que posteriormente se transforma según una distribución o regla para generar una variable aleatoria.

2. Número aleatorio y pseudoaleatorio

En simulación computacional se utilizan generalmente números pseudoaleatorios: son producidos por algoritmos determinísticos, pero están diseñados para comportarse estadísticamente de forma semejante a una secuencia aleatoria. Frecuentemente se trabaja con valores uniformes en el intervalo 0 ≤ U < 1.

3. Propiedades deseables

Uniformidad

Los valores deben distribuirse adecuadamente a lo largo del intervalo; no deberían concentrarse injustificadamente en una zona.

Independencia

Un valor no debería permitir anticipar estadísticamente el siguiente de manera indebida.

Periodo suficientemente largo

La secuencia no debería repetirse demasiado pronto para el estudio que se realiza.

Reproducibilidad

En investigación y validación es útil poder repetir una secuencia usando la misma semilla.

4. Generadores de números aleatorios

Un generador es un procedimiento algorítmico que produce una secuencia. Un concepto importante es la semilla, valor inicial que permite comenzar la secuencia. En muchos generadores, utilizar la misma semilla permite reproducir los mismos valores, algo útil para comparar escenarios bajo condiciones equivalentes.

5. Ejemplo conceptual: generador congruencial lineal

Un ejemplo clásico para comprender la lógica de los generadores es el método congruencial lineal:

Xₙ₊₁ = (aXₙ + c) mod m    y    Uₙ = Xₙ / m

Donde X₀ es la semilla, a es el multiplicador, c el incremento y m el módulo. La selección de parámetros afecta fuertemente la calidad y el periodo de la secuencia. Este método se presenta aquí con finalidad didáctica; los lenguajes actuales disponen de generadores más sofisticados.

6. ¿Por qué se realizan pruebas estadísticas?

No basta con observar una lista y decir que “parece aleatoria”. Las pruebas estadísticas permiten evaluar características de las secuencias. Entre las preguntas de interés están: ¿los números presentan una distribución compatible con uniformidad?, ¿hay evidencia de dependencia?, ¿aparecen patrones sospechosos?

En esta unidad se introduce la finalidad de estas pruebas. El análisis estadístico más profundo de independencia y ajuste se relacionará posteriormente con el análisis de entrada del curso.

7. Variables aleatorias

Una variable aleatoria asigna valores numéricos a los posibles resultados de un fenómeno aleatorio. Puede ser discreta, cuando toma valores contables (por ejemplo, número de pedidos por hora), o continua, cuando puede tomar valores en un intervalo (por ejemplo, tiempo de procesamiento).

Discreta

Número de defectos, clientes, fallas, pedidos o unidades demandadas.

Continua

Tiempo entre llegadas, duración de servicio, peso, temperatura o tiempo hasta una falla.

8. De U(0,1) a una variable del sistema

Los números uniformes pueden transformarse para representar fenómenos con otras distribuciones. En un ejemplo sencillo, si U es uniforme entre 0 y 1 y queremos un tiempo uniforme entre 3 y 7 minutos, podemos usar:

Tiempo = 3 + (7 − 3) × U

Si U = 0.25, el tiempo generado es 4 minutos. Así, diferentes números U producen diferentes tiempos y el modelo deja de comportarse como si cada pieza tardara exactamente lo mismo.

9. Aplicación industrial

Supón que el tiempo de empaque ya no es siempre 5 minutos. Dependiendo de características del producto y del operario, varía entre 3 y 7 minutos. Ahora una sola capacidad fija no describe toda la realidad. Debemos generar observaciones, ejecutar suficientes experimentos y analizar el comportamiento de los resultados.
