Ruta de aprendizaje

Este espacio combina estudio conceptual, ejemplos industriales, ejercicios resueltos, actividades de análisis, laboratorios y evaluación. La simulación no consiste únicamente en utilizar software: comienza por comprender el sistema, formular un problema, construir un modelo y analizar qué información necesita una decisión.

Forma de trabajo: 1) lee el concepto; 2) estudia el ejemplo; 3) intenta el ejercicio antes de abrir la solución; 4) realiza el laboratorio; 5) explica el resultado con tus propias palabras.
UNIDAD 1

Conceptos de Modelamiento y Simulación

Propósito: comprender los fundamentos necesarios para representar un sistema y planear un estudio de simulación.

1. Sistema y pensamiento sistémico

Un sistema es un conjunto de elementos relacionados que interactúan para alcanzar un propósito. En Ingeniería Industrial interesa no solo estudiar cada elemento, sino comprender cómo una modificación en una parte puede afectar el comportamiento global.

Todo estudio necesita una frontera, que determina qué se incluye; un entorno, que reúne factores externos; entradas, que ingresan al proceso; actividades de transformación; y salidas, que representan resultados.

Entidades

Objetos que fluyen o reciben servicio: piezas, clientes, pedidos.

Recursos

Elementos que prestan capacidad: máquinas, operarios, vehículos.

Atributos

Características particulares de una entidad: prioridad, tipo, lote.

Variables de estado

Describen el sistema en un instante: inventario, cola, máquinas ocupadas.

Actividades

Operaciones que consumen tiempo: mecanizado, inspección, transporte.

Eventos

Sucesos que cambian el estado: llegada, salida, falla, reparación.

Ejemplo: centro de distribución

Los pedidos son entidades; los operarios y montacargas son recursos; la prioridad del pedido es un atributo; el número de pedidos esperando es una variable de estado; el alistamiento es una actividad y la llegada de un pedido es un evento.

2. Modelo y modelamiento

Un modelo es una representación simplificada de la realidad creada para un propósito. El modelamiento es el proceso de decidir qué representar, qué relaciones incluir, qué supuestos aceptar y qué nivel de detalle utilizar.

Un modelo puede ser físico (maqueta), conceptual (diagrama y reglas), matemático (ecuaciones) o computacional. En simulación, el modelo conceptual es esencial porque sirve de puente entre el sistema real y su implementación.

Principio de parsimonia: agregar detalle no garantiza un modelo mejor. Debe incorporarse aquello que ayuda a responder el objetivo.
Ejercicio resuelto

Situación: se desea estudiar si una empacadora puede atender la producción diaria. Datos relevantes: jornada disponible, tiempo de empaque, demanda, número de empacadoras y paradas relevantes. El color del equipo o la marca del uniforme no son relevantes para ese objetivo. La selección depende siempre de la pregunta del estudio.

3. ¿Qué es simulación?

La simulación es la experimentación con un modelo para estudiar el comportamiento de un sistema bajo diferentes condiciones. Permite plantear escenarios del tipo “¿qué pasaría si...?” antes de realizar cambios reales.

Puede utilizarse para analizar capacidad, colas, utilización, inventarios, logística, mantenimiento, producción y servicios. No debe confundirse con una simple animación: el propósito es obtener información que apoye el análisis y la decisión.

Ejemplo: antes de comprar una segunda máquina, una empresa puede comparar mediante simulación el escenario actual y el escenario con capacidad adicional, observando producción, utilización, esperas y restricciones.

4. Tipos de simulación

Discreta

El estado cambia cuando ocurren eventos identificables. Ej.: llegada o salida de una pieza.

Continua

Las variables evolucionan continuamente. Ej.: nivel de un tanque.

Determinística

Con las mismas entradas se obtienen los mismos resultados.

Estocástica

Incluye variabilidad aleatoria; diferentes corridas pueden cambiar.

Estática

No representa explícitamente la evolución del sistema en el tiempo.

Dinámica

Representa la evolución temporal del sistema.

Actividad de clasificación

Caso A: línea con llegadas variables, colas y máquinas → discreta, dinámica y normalmente estocástica. Caso B: evolución del nivel de un tanque → continua y dinámica. Caso C: cálculo fijo de capacidad del Laboratorio 1 → determinístico y simplificado.

5. Ventajas de la simulación

Permite experimentar sin interrumpir el sistema real; comparar alternativas antes de invertir; estudiar interacciones complejas; identificar cuellos de botella; explorar políticas; representar variabilidad; evaluar riesgos; acelerar o desacelerar el tiempo del modelo; y comunicar mejor la lógica de un proceso.

6. Desventajas y precauciones

Puede requerir tiempo, datos y conocimiento especializado. Los resultados dependen de la calidad de los datos y supuestos. Una simulación no produce automáticamente la mejor decisión y puede generar falsa confianza si no se verifica y valida. Además, una diferencia entre escenarios puede deberse a variabilidad y requerir análisis estadístico.

Regla: un resultado preciso no compensa un modelo conceptualmente equivocado.

6. Construcción

8. Validación

¿Representa adecuadamente el sistema para el propósito?

9. Experimentación

Definir escenarios y corridas.

10. Análisis

Comparar indicadores y reconocer incertidumbre.

Registrar supuestos, resultados y limitaciones.

Traducir evidencia en decisión.

Verificación vs. validación: ejemplo

Si el modelo indica que una máquina tarda 4 minutos porque así fue programada, estamos revisando su verificación. Si además contrastamos ese comportamiento con datos y expertos para determinar si representa suficientemente la operación real, estamos trabajando la validación.

9. Indicadores productivos para interpretar modelos

Capacidad: máximo procesable bajo condiciones definidas. Throughput: unidades que efectivamente salen. Utilización: proporción de capacidad usada. Cuello de botella: recurso que limita el flujo. Tiempo de espera: tiempo antes de recibir proceso. Tiempo de ciclo: duración definida para completar una operación o ciclo. WIP: trabajo en proceso. Demanda no atendida: demanda que el sistema no logra cubrir.

Capacidad aproximada = (tiempo disponible ÷ tiempo por unidad) × recursos paralelos
Ejemplo resuelto de capacidad

Una estación dispone de 480 min y tarda 6 min/u. Capacidad = 480 ÷ 6 = 80 u/día. Si el tiempo baja a 4 min/u, capacidad = 480 ÷ 4 = 120 u/día. La mejora es de 40 unidades de capacidad diaria bajo estos supuestos.

TALLER U1

Antes del laboratorio

Resuelve primero sin abrir las respuestas.

1. Una máquina dispone de 420 min y tarda 7 min/u. ¿Capacidad?

60 u/día. 420 ÷ 7 = 60.

2. Capacidades: Corte 150, Ensamble 95, Inspección 120. ¿Restricción?

Ensamble, porque presenta la menor capacidad: 95 u.

3. Demanda 130 y capacidad de línea 100. ¿Producción posible y no atendida?

Producción posible = 100; demanda no atendida = 30.

4. ¿Por qué un modelo no debe copiar cada detalle?

Porque debe representar los aspectos necesarios para el propósito. Detalles irrelevantes aumentan complejidad sin mejorar necesariamente la respuesta.

5. ¿Validar y verificar significan lo mismo?

No. Verificar revisa si el modelo fue construido según su lógica; validar evalúa si representa adecuadamente el sistema para el propósito definido.

UNIDAD 2

Generación de números aleatorios

Propósito: comprender cómo se representa la variabilidad en modelos de simulación y cómo una secuencia U(0,1) puede transformarse en variables de un sistema.

1. Variabilidad, incertidumbre y aleatoriedad

En sistemas reales los tiempos de proceso, llegadas, demanda, fallas y reparaciones pueden variar. Un modelo determinístico utiliza entradas fijas; uno estocástico incorpora variables aleatorias para representar incertidumbre relevante.

Una sola corrida estocástica es una realización posible, no necesariamente una conclusión definitiva. Esto prepara el camino para el estudio posterior de réplicas y análisis estadístico de salida.

2. Números aleatorios y pseudoaleatorios

En simulación computacional se utilizan principalmente números pseudoaleatorios: valores producidos por algoritmos determinísticos diseñados para exhibir propiedades estadísticas apropiadas. La base habitual es una secuencia aproximadamente uniforme en 0 ≤ U < 1.

El número U no es necesariamente la variable del sistema. Puede funcionar como materia prima que después se transforma en un tiempo, demanda, cantidad o resultado.

3. Propiedades deseables

Uniformidad

Los valores deben cubrir adecuadamente el intervalo.

Independencia

No deben existir dependencias sistemáticas inconvenientes.

Periodo largo

La secuencia no debe repetirse demasiado pronto.

Reproducibilidad

Debe ser posible repetir experimentos cuando se necesita.

Eficiencia

Debe generar grandes secuencias con costo razonable.

4. Semilla y reproducibilidad

La semilla inicializa el estado de un generador. Con el mismo algoritmo y estado inicial puede reproducirse una secuencia, lo que ayuda a depurar modelos y realizar comparaciones controladas.

No confundir: reproducible no significa “no útil para aleatoriedad”. En simulación, poder repetir una secuencia es una característica valiosa del experimento computacional.

5. Generador congruencial lineal

Como herramienta didáctica se estudia:

Xₙ₊₁ = (aXₙ + c) mod m   ;   Uₙ = Xₙ/m

X₀: semilla; a: multiplicador; c: incremento; m: módulo. Los parámetros influyen en el periodo y calidad. Un generador didáctico ayuda a entender el mecanismo, pero para aplicaciones reales se emplean generadores probados de bibliotecas especializadas.

Ejemplo manual pequeño

Supón X₀=3, a=5, c=1, m=16. X₁=(5×3+1) mod 16=0, por lo que U₁=0/16=0. Luego X₂=(5×0+1) mod 16=1 y U₂=0.0625. El ejemplo muestra que la secuencia surge de una regla y de un estado inicial.

6. Pruebas estadísticas: ¿para qué sirven?

No basta decir que una secuencia “se ve aleatoria”. Se emplean pruebas para evaluar propiedades esperadas. En forma introductoria, interesa estudiar uniformidad e independencia. Pueden aparecer pruebas de frecuencia, medias, chi-cuadrado o Kolmogorov-Smirnov para aspectos de distribución, y pruebas de corridas o autocorrelación para aspectos de dependencia, según la metodología estudiada.

Estas pruebas trabajan con hipótesis y evidencia estadística; superar una prueba no demuestra aleatoriedad absoluta ni garantiza superar todas las demás.

7. Variable aleatoria

Una variable aleatoria asigna un valor numérico a los resultados de un fenómeno aleatorio. Es discreta si toma valores contables y continua si puede tomar valores dentro de intervalos.

8. Distribuciones y transformación

Una distribución de probabilidad describe cómo se asigna probabilidad a los posibles valores. La distribución debe seleccionarse con base en el fenómeno, datos y análisis, no solo porque una gráfica “parezca” tener cierta forma.

Para una variable uniforme entre a y b:

X = a + (b − a)U
Ejemplo resuelto

Tiempo de empaque uniforme entre 3 y 7 min. Si U=0.25: X=3+(7−3)(0.25)=4 min. Si U=0.80: X=3+4(0.80)=6.2 min.

9. Variable discreta mediante intervalos

También podemos asignar intervalos de U a resultados discretos. Ejemplo didáctico: si una demanda toma 10 unidades con probabilidad 0.20, 20 con 0.50 y 30 con 0.30, podemos asociar U de 0.00–0.19 a 10, 0.20–0.69 a 20 y 0.70–0.99 a 30.

Comprueba

Si U=0.63 → demanda 20. Si U=0.82 → demanda 30. Los intervalos representan probabilidades acumuladas.

10. Métodos de generación: panorama

Existen técnicas como transformación inversa, aceptación-rechazo y métodos particulares para ciertas distribuciones. En esta unidad la idea central es comprender la cadena:

Generador → U(0,1) → transformación → variable del sistema → experimento de simulación

TALLER U2

Comprueba antes del laboratorio

1. ¿Número aleatorio y variable aleatoria son lo mismo?

No necesariamente. U(0,1) puede ser una entrada básica que se transforma para generar una variable del sistema.

2. ¿Qué ocurre al repetir un generador con la misma semilla?

Con el mismo algoritmo y condiciones, normalmente se reproduce la secuencia, característica útil para experimentación y depuración.

3. X=5+3U y U=0.4. ¿X?

X=5+3(0.4)=6.2.

4. ¿Promedio 0.5 basta para certificar un generador?

No. Un promedio por sí solo no demuestra uniformidad, independencia ni calidad general.

5. Clasifica: número de fallas y tiempo hasta falla.

Número de fallas: discreta. Tiempo hasta falla: continua.
